About Me

Documentation isn't just a nice-to-have—it's the difference between product success and user frustration. I create enterprise-grade documentation that bridges the gap between complex products and the people who use them.

As a Technical Writer at Red Hat, I specialize in creating documentation for OpenShift, security platforms, and enterprise cloud-native technologies. I combine traditional documentation expertise with modern approaches: Jobs-to-be-Done (JTBD) frameworks and AI-powered workflows. But I don't just document features—I document solutions to user problems.

My work includes component documentation, administration guides, release notes, and user guides for enterprise customers and developers. I simplify complex concepts like Kubernetes operators, CSI drivers, and security analyzers into clear, actionable content.

Currently, I'm leading the implementation of Jobs-to-be-Done (JTBD) methodology across OpenShift documentation teams at Red Hat. This isn't just a documentation change—it's a cultural shift bringing together Engineering, UX, Marketing, and Support to create unified, user-goal-oriented content. I've built custom AI-powered tools (Claude skills and Gemini gems) to automate JTBD analysis, extract job statements from existing documentation, and generate goal-based navigation structures at scale.

Beyond helping humans find answers faster, this approach makes our documentation AI-ready through Answer Engine Optimization (AEO). When content is structured around user goals rather than features, LLMs can provide more accurate, contextual responses—making our docs more discoverable for both human users and AI systems.

My toolkit spans traditional platforms (Confluence, OxygenXML, AsciiDoc) to modern systems (Document360, Componize) to AI assistants—all focused on one goal: making complex enterprise products easier to understand and use.
